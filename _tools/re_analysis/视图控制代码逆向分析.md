## 一、事件管线总览

ZBrush 的鼠标/视图事件按以下管线流动（WM_消息 → … → 视图更新）：

```
WM_MOUSEMOVE / WM_LBUTTONDOWN ...
  → 事件发送器（WndProc 侧，RVA 0x17Bxxxx）
  → 事件推入队列（0xF11D0 / 0xF12A0 / 0xF1370）
  → 事件分发器 0xF14D0（弹出一个事件对象，调用其 vtable+0xA0）
  → 事件处理器 0x180A0F0（事件对象 vtable 0xDAAE590 的 +0xA0 槽）
  → 路由器 0x1807950（视图对象 vtable +0x78 槽，按事件类型分派）
       ├─ 0x50001 移动 → 0x1807C6D（三分支，最终到控制器或视图处理器）
       ├─ 0x20001 视图更新 → 0x18084E7（读视图状态并重绘）
       └─ 出口 r14d==0 时 → 0x17BA7B0（视图文档处理器！关键）
  → 控制器 0x5E5E40（[view+0x1B0] 对象 vtable+0x78）
       └─ 0x50000 鼠标 → 0x5E7FAA → 0x1830600 + 0x5E4D90
            └─ 0x50001 case → 0x5E539A（导航模式分派）
```

## 二、视图导航（旋转/平移/缩放）的真正代码链

**这是本次逆向的关键新发现**：活动视图的移动/导航处理不在控制器
0x5E4D90 里，而在“视图文档处理器”链：

```
路由器 0x1807950 出口（r14d==0）
  → 0x17BA7B0  视图文档处理器（0xFC0 字节，按事件类型二次分派）
       └─ 0x50001 移动 case → 0x17BB118
            ├─ 活动视图 & 标志 0x200 → 0x17ACA40（更新各视图光标位置）
            └─ 活动视图（常规）    → vtable+0x1B8 = 0x17ABFD0（★导航核心）
            └─ 非活动视图          → vtable+0x1F0 = 0x180A080（画布命中测试）
  → 0x17ABFD0  活动视图移动处理器（0x3DA 字节）
       ├─ 计算新位置（坐标变换 0xD54130 / 0xD541A0）
       ├─ 调用 0x17BC020（矩形/增量数学，0x66C 字节）
       └─ vtable+0x110 = 0x17BBDC0 → ★把新位置写入视图对象 +0x38/+0x3C
  → 0x17BBDC0  位置写入函数：
       mov [rbx+0x38], eax   ; 视图 X
       mov [rbx+0x3C], eax   ; 视图 Y
```

### 关键函数表

| RVA | vtable 槽 | 作用 |
|---|---|---|
| 0x17BA7B0 | — | 视图文档处理器（鼠标/导航总入口） |
| 0x17BB118 | — | 0x50001 移动事件处理器 |
| 0x17ABFD0 | 视图 vtable+0x1B8 | **活动视图导航处理器（旋转/平移/缩放入口）** |
| 0x17BC020 | — | 导航矩形/增量数学 |
| 0x17BBDC0 | 视图 vtable+0x110 | **视图位置写入（+0x38/+0x3C）** |
| 0x180A080 | 视图 vtable+0x1F0 | 画布命中测试（返回 2/9） |
| 0x17ACA40 | — | 更新各视图光标位置 |
| 0x5E5E40 | [view+0x1B0]+0x78 | 控制器（鼠标/工具分派） |

## 三、视图对象结构（部分）

```
视图对象（事件对象，vtable 0xDAAE590）：
  +0x38/+0x3C  当前光标/位置 X,Y（float）
  +0x48..+0x54 画布边界
  +0xDD        计数器
  +0xDE        标志（bit 0x200 = 特殊导航模式）
  +0xE0        视图标志（float）
  +0x1B8       子对象指针（+0x3C..0x48 为视口矩形，旋转时变化）
  +0x1B0       控制器对象
```

## 四、之前所有尝试为何失败（结论）

1. 0x5F7DC0 / 0x5F7890 / 0x5EB390 / 0x5EDFC0 / 0x5F0FC0（控制器模式动作）
   ——旋转时**从未被调用**（blocked 计数为 0），它们不是旋转路径。
2. 0x5E4D90 的 switch case 0（0x5E539A）被阻断后旋转只是变卡顿
   ——真正的旋转在 0x17BA7B0 → 0x17ABFD0 链上，控制器 case 0 只是辅助。
3. 硬件断点/调试寄存器在本机对 ZBrush 不可用
   （SetThreadContext 被系统拒绝；headless 布执行断点导致 #DB 未处理崩溃）。
4. 0x1807DEC 转发点不可补丁（存在另一条路径 0x1807DF3 跳入补丁区）。

**最终建议钩子点**：0x17ABFD0（活动视图导航处理器入口，16 字节干净窗口）
或 0x17BBDC0（位置写入，入口小函数）。左键按下且未按 Ctrl 时让其一进入口
直接返回，即可从源头阻断旋转/平移/缩放，且不影响雕刻（雕刻不走此函数）。
